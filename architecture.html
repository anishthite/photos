architecture

How photos.thite.site works — a fully static photo library: files on disk become a JSON index, and Cloudflare Pages serves the whole thing. No server, no database, no build step.

Your machine

photos/originals on disk — subfolders become albums (photos/hike, photos/city…)
↓ scripts/add_photos.sh
scripts/build_library.pyscans photos/, reads EXIF DateTimeOriginal via Pillow (mtime fallback) → data/photos.json
↓
index.htmlthe entire app — day-grouped grid, search, lightbox — plus et-book fonts, thite.site style
↓ wrangler pages deploy .

Cloudflare

Pages project “photos”serves the static folder at photos-erv.pages.dev — live now
↓ custom domain attached via API
thite.site zone (DNS)needs one CNAME: photos → photos-erv.pages.dev (proxied) — token here lacks DNS scope, so add it in the dash or hand me a DNS-scoped API token
↓ once DNS exists, Cloudflare auto-issues SSL
photos.thite.siteHTTPS on Cloudflare’s edge, cached worldwide
↓
Visitor’s browserfetches index.html + data/photos.json, renders the grid client-side

Add-a-photo flow

  1. scripts/add_photos.sh ~/Desktop/vacation — copies images into photos/ (optional album name becomes a subfolder)
  2. build_library.py regenerates data/photos.json with dates, albums, timestamps
  3. wrangler pages deploy ships the folder to Pages (~2 s)
  4. Site picks it up on next load — fetch('data/photos.json', no-store)

Source of truth: github.com/anishthite/photos (code + scripts; photo contents gitignored). Status: pages.dev URL live · custom domain pending the one DNS record.
